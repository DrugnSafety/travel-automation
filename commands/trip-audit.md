사용자가 여행 페이지 점검을 요청했다. **`travel-quality-loop` 스킬**을 실행하라.

## 대상 확정

`$ARGUMENTS`에 노션 URL이나 trip_slug가 있으면 그것을 쓴다. 없으면 `/tmp/*/state.json`을 찾거나 `search`로 여행 페이지를 찾아 사용자에게 확인받는다.

## 12개 체크

**S1 치명적 — 반드시 수정**
- C1 한글 파손 (기계 탐지 + 고유명사 육안 대조. "열로스톤", "통밥집" 류는 정규식에 안 걸린다)
- C2 요일 정합성 (전 페이지 대조. 한 곳 틀리면 전체 점검)
- C3 하위 페이지 아카이빙 여부
- C4 사실 오류 (날짜 산술, 박수 합계, 비용 소계, 전화번호, 요금·시간)

**S2 중요**
- C5 스팟당 이미지 수 (소제목마다 별도 배정 포함)
- C6 이미지 URL 200 검증
- C7 날짜별 지도 섹션 4요소
- C8 좌표 바운딩 박스 (부호 누락 검출)
- C9 스팟별 5개 블록 (관람 포인트·역사·주차·추천 시간대·팁)

**S3 개선**
- C10 문체 (`moai-content:humanize-korean` 기준)
- C11 링크 무결성
- C12 접근성 정보 (고령자·유아 동반)

## 루프

수집 → 심각도 정렬 → 자동 수정 → 재검증. **findings가 0이 될 때까지 최대 3회.**

페이지가 많으면 감사(읽기)는 Agent로 병렬화하되 **수정은 순차로** 한다. 같은 페이지에 동시에 쓰면 충돌한다.

## 출력

감사 리포트 표 + 수정한 항목 목록 + 수동 확인 필요 항목.
