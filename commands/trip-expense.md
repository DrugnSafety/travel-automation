사용자가 여행 비용을 관리할 곳을 요청했다. `travel-expense-db` 스킬로 처리한다.

## 만드는 것

| 산출물 | 역할 |
|---|---|
| **💵 여행 지출 관리** (데이터베이스) | 항목 단위 원장. 영수증이 여기 쌓인다 |
| **🧾 여행 경비 총괄** (페이지) | 사람이 읽는 요약. 소계·현금흐름·카드 배분·리스크 |

둘 다 만든다. 데이터베이스만 있으면 읽히지 않고, 페이지만 있으면 갱신되지 않는다.

## 실행 순서

1. `trip-brief.json`에서 통화·인원·일수·결제 카드·확정 예약을 읽는다. 없으면 AskUserQuestion으로 묻는다
2. 데이터베이스를 생성한다. **영수증 자동 등록을 쓸 계획이면 `가맹점`·`영수증`(FILES)·`원화폐 금액` 칼럼을 반드시 포함**한다
3. 확정 예약을 실제 금액과 확인번호로 넣는다. 나머지는 예상 또는 미확정으로 넣되 **지어내지 않는다**
4. 경비 총괄 페이지를 만든다
5. 반환된 **data source ID를 `state.json`의 `expense_data_source_id`에 저장**한다. 이후 모든 등록이 이 ID로 이뤄진다

## 반드시 검산

작성 후 계산기로 확인한다. 아래 넷은 과거에 반복해서 틀렸다.

1. 분류별 소계의 합 = 총액
2. 상태별 소계의 합 = 총액 (환불예정 제외)
3. 비중 백분율의 합 = 100% — 반올림으로 103%가 된 사고가 실제로 있었다
4. 최악 시나리오 총액 = 현재 총액 + 개별 리스크 금액의 합

**환불성 보증금은 총액에서 뺀다.** 넣으면 여행 경비가 실제보다 커 보인다. 대신 "일시적으로 묶이는 돈"으로 따로 보여준다.

## 이미 비용 페이지가 있을 때

지우지 않는다. 산출 근거가 거기 남아 있다. 옛 페이지 맨 위에 구버전 표시와 새 페이지 링크를 넣고, 인원 수·날짜 같은 전제가 바뀌었으면 그 사실도 함께 적는다.

`--rebuild`가 오면 기존 데이터베이스를 지우지 말고 **요약 페이지만 현재 행 기준으로 다시 계산**한다.
