사용자가 여행 페이지의 시각 자료 보강을 요청했다.

## 두 가지는 서로 다른 산출물이다

| | AI 일러스트 (`travel-illustration`) | 스톡 사진 (`travel-image-search`) |
|---|---|---|
| 무엇 | 그날의 동선·일정을 요약한 오리지널 삽화 | 실제 장소의 사진 |
| 개수 | 여정 1장 + 날짜당 1장 | 스팟당 2장 이상 + 소제목마다 1장 |
| 위치 | 페이지 최상단 | 스팟 섹션 안 |

**하나가 다른 하나를 대체하지 않는다.** `--all`이 기본이며 둘 다 만든다.

## 사진 (`travel-image-search`)

- Pexels CDN. **검색으로 확인한 ID만 쓴다** — 임의 숫자를 넣으면 200이 나오지만 무관한 사진이다
- 용도별 폭: 커버 `w=1600` / 본문 `w=1280` / 2단 배치 `w=800` / 표 썸네일 `w=640`
- `auto=compress&cs=tinysrgb` 항상 유지
- **삽입 전 전 URL을 curl로 200 검증**. 검색 결과에 있어도 삭제된 사진이 있다
- 여행 시기와 계절이 맞는 사진을 고른다 (8월 여행에 설경 금지)
- 체크리스트·비용 페이지에도 2~3장 넣는다. 텍스트만 있는 페이지는 읽히지 않는다

## 일러스트 (`travel-illustration`)

각 날짜 그림에 4가지를 반영한다.

1. **동선 순서** — 실제 방문 순서대로 좌→우 배치
2. **시간대** — 방문 시각의 광질 (새벽 blue hour / 정오 high sun / 골든아워 / 트와일라잇)
3. **계절 특성** — `trip-brief.json`의 `season.traits`를 시각 요소로 변환
4. **시간 정보 표기** — 배너에 `Day N · 월/일 (요일) · 구간`, 하단에 시각 라벨

전체 요약 일러스트는 **일러스트 지도(illustrated map)** 형식이 효과적이다. 경로를 점선으로 그리고 랜드마크 비네트를 순서대로 배치한다.

**비용 관리**: 1장으로 방향을 먼저 확인받고, 톤이 확정되면 일괄 생성한다. 2~3장씩 나눠 실행한다. 생성 이력을 `state.json`에 남겨 중복 과금을 막는다.

생성 후 이미지를 실제로 열어 **배너의 날짜·요일 철자가 맞는지 확인**한다. 모델이 텍스트를 틀리는 경우가 있다.

## 검증

`travel-image-validator`로 전 URL을 재검증하고, `travel-quality-loop`의 C5·C6 체크를 통과시킨다.
