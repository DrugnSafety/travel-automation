# Travel Expense DB — 지출 관리 데이터베이스 · 경비 총괄 페이지

## 이 스킬이 만드는 두 가지

| 산출물 | 성격 | 용도 |
|---|---|---|
| **💵 여행 지출 관리** (데이터베이스) | 원장(ledger) | 항목 단위 입력·수정·필터. 영수증이 여기 쌓인다 |
| **🧾 여행 경비 총괄** (페이지) | 요약본 | 사람이 읽는 화면. 소계·현금흐름·카드 배분·리스크 |

**둘은 역할이 다르다.** 데이터베이스는 기계가 쓰고, 페이지는 사람이 읽는다. 숫자를 고칠 때는 항상 데이터베이스를 먼저 고치고 페이지를 다시 계산한다. 페이지만 고치면 다음 영수증이 들어올 때 되돌아간다.

## 만들기 전에 확정할 것

`trip-brief.json`이 있으면 거기서 읽고, 없으면 사용자에게 묻는다.

| 항목 | 왜 필요한가 |
|---|---|
| 기준 통화 | 표시 통화가 섞이면 합계가 무의미해진다 |
| 인원 수 | 1인당 금액 산출 |
| 여행 일수 | 1일당 금액 산출 |
| 결제 카드 목록 | 카드별 배분과 보장 조건 판단 |
| 환불성 항목 유무 | 보증금은 총액에서 빼야 한다 |

## 데이터베이스 스키마

`notion-create-database`에 SQL DDL로 넘긴다. 분류(SELECT) 옵션은 **여행 유형에 맞게 조정**하되, 아래를 기본값으로 삼는다.

```sql
CREATE TABLE (
  "항목" TITLE,
  "분류" SELECT('항공':blue, 'RV':green, '렌트카':purple, '숙박':orange,
                '식비':yellow, '입장료':pink, '장비·용품':brown,
                '연료':red, '기타':gray),
  "금액(USD)" NUMBER FORMAT 'dollar',
  "상태" SELECT('확정·결제완료':green, '확정·미결제':blue, '예상':yellow,
                '미확정':red, '환불예정':gray),
  "결제수단" SELECT('Amex':blue, 'Chase':green, '현장 결제':orange, '미정':gray),
  "결제일" DATE,
  "확인번호" RICH_TEXT,
  "메모" RICH_TEXT
)
```

영수증 자동 등록을 쓸 계획이면 **아래 세 개를 반드시 추가**한다. `travel-receipt-ocr`이 이 칼럼들을 전제로 동작한다.

```sql
ADD COLUMN "가맹점" RICH_TEXT;
ADD COLUMN "영수증" FILES;
ADD COLUMN "원화폐 금액" RICH_TEXT
```

- **가맹점** — OCR로 읽은 상호명 원문. 중복 판정의 핵심 키
- **영수증** — 원본 이미지. 나중에 세금·환급·분쟁에서 이것만 있으면 된다
- **원화폐 금액** — `CAD 84.20 @1.37` 처럼 원문 통화와 환율을 문자열로 남긴다. 숫자 칼럼은 기준 통화 하나로 통일하고, 원문은 여기 보존한다

### 상태 값의 의미를 헷갈리지 말 것

| 상태 | 뜻 | 총액 포함 |
|---|---|---|
| 확정·결제완료 | 이미 돈이 나갔다 | ✅ |
| 확정·미결제 | 계약은 됐고 현장에서 낸다 | ✅ |
| 예상 | 아직 안 정해졌고 추정치다 | ✅ |
| 미확정 | 예약 자체가 안 됐다 | ✅ (변동 리스크로 별도 표시) |
| **환불예정** | 보증금처럼 돌아올 돈 | ❌ **총액에서 제외** |

환불성 보증금을 총액에 넣으면 여행 경비가 실제보다 커 보인다. 대신 "일시적으로 묶이는 돈"으로 따로 보여준다.

## 시드 항목 만들기

`trip-brief.json`의 교통·숙박·일정에서 뽑아낸다. 없는 항목을 지어내지 말고, **모르면 '미확정'으로 넣어 눈에 띄게 둔다.**

- 확정된 예약(항공·차량·숙소)은 확인번호와 함께 그대로 넣는다
- 식비·연료·입장료는 계산 근거를 메모에 남긴다 (`613마일 ÷ 10mpg × $3.90`)
- 장비·용품은 **현지에서 사야 하는 것**을 빠뜨리기 쉽다. 렌털 차량의 키트 포함 여부를 확인해 반영한다

## 경비 총괄 페이지 구성

순서를 지킨다. 사용자가 가장 먼저 알고 싶은 것부터 나온다.

1. **한눈에 보기** — 총액 / 이미 낸 돈 / 확정됐지만 미결제 / 미확정 / 변동비 / 묶이는 돈 / 1인당 / 1일당
2. **분류별 소계** — 금액·비중·확정도. 비중은 **합계가 100%가 되는지 반드시 검산**한다
3. **언제 얼마가 나가나** — 시점순 현금 흐름. 이 표가 실무에서 가장 많이 쓰인다
4. **카드 배분** — 어느 결제를 어느 카드로 해야 하는지와 그 이유
5. **보험 결정 근거** — 거절한 옵션과 대체 수단. 나중에 "왜 안 들었더라" 하고 되묻는 일을 막는다
6. **당초 예상 대비 변화** — 확정되면서 얼마나 줄었는지
7. **아직 흔들릴 수 있는 금액** — 미확정 항목의 위쪽 리스크
8. **현금 소요** — 카드가 안 되는 곳

### 현금 흐름 표가 이 페이지의 핵심이다

총액보다 **"8/14 하루에 얼마가 빠져나가는가"** 가 실제로 문제를 일으킨다. 렌털 보증금과 잔금이 같은 날 겹치면 카드 한도에 걸려 픽업 자체가 지연된다. 그래서 다음을 명시한다.

- 하루에 몰리는 금액이 있으면 **경고 콜아웃**으로 띄운다
- 등록 카드의 한도와 해외 사용 정지 여부를 출발 전에 확인하라고 적는다
- 유출 합계와 순지출을 구분해 적는다 (환불액 때문에 두 숫자가 다르다)

## 반드시 검산할 것

작성 후 계산기로 확인한다. 이 네 가지가 과거에 반복적으로 틀렸다.

1. **분류별 소계의 합 = 총액**
2. **상태별 소계의 합 = 총액** (환불예정 제외)
3. **비중 백분율의 합 = 100%** (반올림으로 103%가 되는 사고가 실제로 있었다)
4. **현금 흐름 표의 유출 합계 − 환불액 = 순지출**

최악 시나리오 총액을 적을 때는 **개별 리스크 금액을 더한 값과 일치하는지** 확인한다. 어림수로 적으면 어긋난다.

## 기존 비용 페이지가 이미 있을 때

새로 만들되 **옛 페이지를 지우지 않는다.** 항목별 산출 근거가 거기 남아 있는 경우가 많다. 대신 옛 페이지 맨 위에 구버전 표시와 새 페이지 링크를 넣는다.

```
> ⚠️ 이 페이지는 계획 단계의 추정치입니다 (구버전)
> 최신 숫자는 [🧾 여행 경비 총괄]과 [💵 여행 지출 관리]를 보세요.
```

옛 페이지의 인원 수·날짜 가정이 바뀌었다면 그 사실도 함께 적는다. 숫자만 남겨두면 나중에 어느 쪽이 맞는지 알 수 없다.

## Notion 작성 시 주의

`notion-travel-page` 스킬의 함정이 여기에도 그대로 적용된다.

- **한글은 문자 그대로 입력한다.** 유니코드 이스케이프로 조립하면 파손된다
- 금액의 `$`는 `\$`, 물결표는 `\~`, 카드 마스킹의 `*`는 `\*`
- 페이지 아이콘에 이모지를 넣었으면 **제목에는 다시 넣지 않는다**
- 부모 페이지에 `replace_content`를 쓰지 않는다 (하위 페이지가 아카이빙된다)
- 데이터베이스를 만들면 반환된 **data source ID(`collection://...`)를 기록해둔다.** 이후 모든 행 추가·조회가 이 ID로 이뤄지고, 페이지 URL과는 다른 값이다
