# Travel Naver Search — 한국인 관점 실전 정보 수집

## 왜 반드시 필요한가

영문 웹 검색만으로 만든 여행 가이드에는 구조적 공백이 있다. 다음은 영문 소스에 거의 없지만 한국인 여행자에게는 결정적인 정보다.

- 한국 신용카드·체크카드의 현지 결제 실패 사례와 대안
- 한식 조달 경로 (H마트 위치, 컵라면 반입, 고추장 소분 요령)
- 한국 렌터카/RV 예약 대행업체의 실제 후기와 함정
- 아이·고령 부모 동반 시 한국 가족이 실제로 겪은 문제
- 한국 출발 항공편 기준 시차 적응 전략
- 한국어 가이드 투어·한인 민박 정보
- 국제운전면허증 인정 여부, 현지 경찰 검문 대응
- 한국인이 자주 놓치는 예약·입장 규정

**따라서 스팟마다 최소 1회 네이버 검색을 수행한다.** 이것은 선택이 아니라 `travel-research`의 필수 하위 단계다.

---

## 도구 선택

| 도구 | 언제 쓰는가 | 특성 |
|---|---|---|
| `NaverSearch-search_blog` | **기본값.** 실제 방문 후기, 상세 일정, 사진 위치 | 개인 경험, 정보 밀도 높음 |
| `NaverSearch-search_cafearticle` | 심화 정보, 문제 해결, 장비·차량 논의 | 커뮤니티 집단 지성. 낚시성 글이 적음 |
| `NaverSearch-search_kin` | "이럴 때 어떻게" 류의 구체적 질문 | 실패 사례 확보에 유용 |
| `NaverSearch-search_news` | 규정 변경, 사고, 시즌 이슈 | 최신성 확인 |
| `NaverSearch-search_webkr` | 위 검색이 빈약할 때 폭넓게 | 커버리지 보완 |
| `NaverSearch-search_local` | **국내 여행 한정** | 해외 여행지에는 결과 없음 |
| `NaverSearch-search_encyc` | 배경 지식, 용어 설명 | 아이 교육용 콘텐츠에 유용 |

> 해외 여행에서 `search_local`은 결과를 거의 반환하지 않는다. 국내 여행일 때만 쓴다.

## 검색 전략

### 1. 스팟별 3단 검색

각 스팟마다 최소 3개 쿼리를 던진다. 하나로는 편향된다.

```
① 기본 후기   : "{장소명 한글} 후기"
② 상황 특화   : "{장소명 한글} {여행 조건}"      예) "옐로스톤 캠핑카 아이"
③ 문제 해결   : "{장소명 한글} 주차" / "예약" / "시간"
```

### 2. 여행 조건별 확장 쿼리

`trip-brief.json`의 조건을 쿼리에 결합한다.

| 조건 | 쿼리 예시 |
|---|---|
| RV/캠핑카 | `"{지역} 캠핑카 여행 후기"`, `"{지역} RV 렌트 주의"`, `"{지역} 덤프스테이션"` |
| 아동 동반 | `"{지역} 아이와 여행"`, `"{지역} 유아 동반"`, `"{장소명} 아이 힘들"` |
| 고령자 동반 | `"{지역} 부모님 모시고"`, `"{장소명} 어르신"` |
| 국립공원 | `"{공원명} 캠핑장 예약"`, `"{공원명} 동선"`, `"{공원명} 몇박"` |
| 렌터카 | `"{지역} 렌터카 편도"`, `"{지역} 국제운전면허"` |
| 항공 | `"{출발지} {도착지} 경유"`, `"{항공사} 수하물"` |

### 3. 정렬 옵션

- `sort: "sim"` (기본) — 관련도순. 대표적인 정보를 얻을 때
- `sort: "date"` — 최신순. **요금·운영시간·규정처럼 변하는 정보는 반드시 date로 재검색**한다

여행 정보는 노후화가 빠르다. 2년 이상 된 글의 요금·운영시간은 신뢰하지 않는다.

### 4. 결과 개수

`display: 10`이 기본. 핵심 스팟은 `display: 20`으로 늘리고, 부수적인 경유지는 5로 줄인다.

## 결과 처리

### 검증 원칙

네이버 블로그에는 **협찬·광고 글**이 섞여 있다. 다음 신호를 확인한다.

| 신뢰 신호 | 주의 신호 |
|---|---|
| 구체적 시각·금액·좌석번호 | "제공받아 작성", "체험단" |
| 실패담·불만 포함 | 장점만 나열 |
| 사진 EXIF 시기와 본문 일치 | 업체 링크 반복 |
| 댓글에 질답이 오감 | 동일 문구가 여러 블로그에 반복 |

**요금·운영시간·규정은 블로그를 근거로 쓰지 않는다.** 블로그는 "이런 게 있다"는 단서로 쓰고, 확정은 공식 사이트로 한다.

### 교차 검증 절차

```
네이버에서 발견 → 영문 공식 소스로 확인 → 둘 다 일치하면 채택
                                        → 불일치하면 공식 소스 채택 + "블로그와 상이" 메모
```

### 리서치 파일 기록 형식

`research/{spot_id}.md`에 다음 섹션을 추가한다.

```markdown
### 🇰🇷 한국인 여행자 실전 정보

**출처**: 네이버 블로그 {N}건 · 카페 {M}건 (검색일 {날짜})

- {실전 팁 1} — 출처: [{블로그명}]({URL})
- {실전 팁 2} — 출처: [{카페명}]({URL})

**주의 사항으로 반복 언급된 것**
- {2건 이상에서 공통으로 언급된 문제}

**공식 정보와 다른 점**
- {블로그 주장} ↔ {공식 확인 결과}
```

**2명 이상이 같은 문제를 언급하면 실제 문제일 가능성이 높다.** 이런 항목은 노션 페이지의 팁 블록에 우선 반영한다.

## 출처 표기

네이버 검색 결과를 인용했으면 **반드시 출처 링크를 남긴다.** 노션 페이지 하단에 다음 형식으로 정리한다.

```markdown
> 🔍 **참고한 한국어 후기**
>
> • [{제목}]({URL}) — {한 줄 요약}
> • [{제목}]({URL}) — {한 줄 요약}
```

API 응답의 `title`과 `description`에는 `<b>` 태그가 섞여 있다. 노션에 넣기 전에 제거한다.

```python
import re, html
def clean(s):
    return html.unescape(re.sub(r'</?b>', '', s or '')).strip()
```

## 국내 여행일 때 추가 활용

`search_local`로 상호명·주소·전화번호·영업시간을 정확히 확보한다.

```
NaverSearch-search_local(query="{지역} {업종}", sort="comment", display=5)
```

`sort: "comment"`는 리뷰가 많은 순이라 실제 영업 중인 곳을 찾는 데 유리하다.

`datalab_search`로 특정 여행지의 검색량 추이를 보면 성수기·비수기를 데이터로 확인할 수 있다.

## 병렬 실행

스팟이 많으면 Agent tool로 병렬화한다. 각 에이전트에 다음을 명시한다.

```
- 담당 스팟 목록
- 스팟당 최소 3개 쿼리 (기본 후기 / 조건 특화 / 문제 해결)
- 협찬 글 필터링 기준
- 출처 URL 필수 수집
- research/{spot_id}.md 의 "🇰🇷 한국인 여행자 실전 정보" 섹션에 기록
```

## MCP가 없을 때

PlayMCP NaverSearch 도구를 쓸 수 없으면 사용자에게 알린다.

> 네이버 검색 MCP가 연결되어 있지 않아 한국어 후기 수집을 건너뜁니다. 영문 소스 기반으로 진행하되, 한국인 여행자 관점의 정보(카드 결제, 한식 조달, 국제면허 등)는 별도 확인이 필요합니다.

대체 수단으로 `WebSearch`에 한국어 쿼리를 넣되(`"{장소명} 후기 블로그"`), 네이버 본문 접근이 제한적이라 커버리지가 떨어진다는 점을 감안한다.
