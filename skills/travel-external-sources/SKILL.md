# Travel External Sources — 소스 라우팅과 신뢰도

## 원칙: 정보 유형이 소스를 결정한다

여행 정보는 종류마다 신뢰할 수 있는 소스가 다르다. 하나의 검색 도구로 전부 해결하려 하면 정확도가 때어진다.

| 정보 유형 | 1순위 | 2순위 | 블로그·커뮤니티 사용 |
|---|---|---|---|
| **입장료·운영시간·규정** | 공식 기관 사이트 | 공식 앱 | ❌ 근거로 쓰지 않음 |
| **예약 가능 여부** | 예약 운영사 (전화 우선) | 예약 사이트 | ❌ |
| **좌표·주소** | 공공 데이터, 지도 MCP | 지도 URL 파싱 | ❌ |
| **실제 소요 시간·혼잡도** | 리뷰 MCP | 커뮤니티 | ✅ 유용함 |
| **주차 실태·대형차 가능 여부** | 커뮤니티·후기 | 공식(대개 정보 없음) | ✅ 여기가 거의 유일한 통로 |
| **한국인 특화 정보** | 네이버 블로그·카페 | — | ✅ 필수 |
| **항공권 가격** | 항공 검색 MCP | 항공사 직판 | ❌ |
| **숙박 가격·평점** | 숙박 검색 MCP | 직판 | ⚠️ 참고만 |
| **날씨·기후 평년값** | 기상 기관 | — | ❌ |
| **안전·사고 이력** | 공공기관 발표, 뉴스 | — | ⚠️ |

> **핵심**: 공식 사이트에는 없고 커뮤니티에만 있는 정보가 있다. 대형차 주차 가능 여부, 실제 도착 시각별 혼잡도, 화장실 상태, 아이가 힘들어하는 구간 같은 것들이다. 이런 정보를 위해 커뮤니티를 쓰되, **요금·시간·규정은 절대로 커뮤니티를 근거로 쓰지 않는다.**

## 연결 가능한 커넥터

### 이 플러그인의 `.mcp.json`에 정의된 것

| 서버 | 용도 | 대표 도구 |
|---|---|---|
| **kiwi-flights** | 항공편 검색·가격 비교 | `search-flight` |
| **trivago-hotels** | 숙박 가격·평점 비교 | `trivago-accommodation-search`, `trivago-accommodation-radius-search` |
| **google-maps** | 장소 상세·리뷰·영업시간 | `google_maps_search`, `google_maps_place_details`, `google_maps_nearby_search` |
| **lilt-translation** | 현지 언어 표현 번역 | `translate_text` |

### 세션에 연결되어 있으면 활용

| 서버 | 용도 | 비고 |
|---|---|---|
| **PlayMCP — NaverSearch** | 한국어 블로그·카페·지식iN·지역 | `travel-naver-search` 스킬이 전담. **필수** |
| **Notion** | 가이드북 생성 | 산출물의 기본 |
| **Google Calendar** | 일정 등록 | |
| **claude-in-chrome** | 로그인 필요한 페이지 열람 | 2회 실패 시 포기 |

### 레지스트리에서 추가로 연결할 만한 것

`SearchMcpRegistry`로 확인하고, 필요하면 `SuggestConnectors`로 제안한다.

| 서버 | 여행에서의 쓸모 | 인증 |
|---|---|---|
| **TomTom Maps** | 지오코딩, POI 검색, 경로 계산, 실시간 교통. 좌표 정확도가 필요할 때 최선 | 필요 |
| **Tripadvisor** | 호텔·명소 리뷰. 한국 커뮤니티와 교차 검증용 | 불필요 |
| **Expedia** | 항공+숙박 패키지 | 불필요 |
| **DirectBooker** | 호텔 직판 최저가 | 불필요 |
| **lastminute.com** | 임박 항공권 | 불필요 |
| **Felt Maps** | 공유 가능한 웹 지도 생성 (`create_map`) | 필요 |
| **Wyndham** | 특정 체인 숙박 | 불필요 |
| **Otto Travel** | 출장 예약 관리 | 필요 |

**커넥터가 없다고 작업을 멈춰지 않는다.** 없으면 `WebSearch` + `WebFetch`로 공식 사이트를 직접 조회하고, 사용자에게 "이 커넥터를 연결하면 더 정확해진다"고 한 번만 알린다.

## 공공·공식 소스 (커넥터 없이도 가장 정확)

| 지역·유형 | 소스 |
|---|---|
| 미국 국립공원 | `nps.gov` — 요금, 운영시간, 도로 상황, 클리닉, 츠핑장 |
| 미국 츠핑장 예약 | `recreation.gov` (연방), 각 컨세션 운영사 |
| 미국 주립공원 | 각 주 공원청. **국립공원 연간 패스가 통하지 않는다** |
| 한국 | 한국관광공사 TourAPI, 각 지자체 관광포털 |
| 일본 | JNTO, 각 현 관광연맹 |
| 유럽 | 각국 관광청, 국영 철도 |
| 기상 | NOAA/기상청 평년값 |
| 항공 안전·수하물 | 각 항공사 공식, TSA |

**요금과 운영시간은 반드시 공식 사이트에서 확인한다.** 특히 다음은 자주 바뀐다.
- 국립공원 입장료·연간 패스 가격
- 셔틀·보트 운항 시기
- 시설 폐쇄·공사 일정
- 츠핑장 개방 기간

## 교차 검증 규칙

### 3단 검증

```
① 공식 소스에서 확정   → 요금·시간·규정
② 리뷰/커뮤니티로 보완 → 실제 소요 시간, 혼잡, 주차 실태
③ 상충하면 공식 채택   → 차이를 페이지에 명시
```

### 신뢰도 표기

리서치 파일과 노션 페이지에 근거의 성격을 남긴다.

| 표기 | 의미 |
|---|---|
| 출처 링크 있음 | 공식 소스 확인 완료 |
| "{연도} 기준" | 그 시점 정보. 변경 가능 |
| "현장 확인 필요" | 확정 소스를 못 찾음 |
| "후기 기준" | 커뮤니티 정보. 공식 확인 안 됨 |

**모르면 모른다고 쓴다.** 그럴듯한 숫자를 지어내는 것이 가장 나쁘다.

### 반복 언급 가중

커뮤니티 정보는 **독립된 2건 이상에서 같은 내용이 나오면** 신뢰도를 올린다. 1건뿐이면 "후기 기준"으로 표시한다.

## 예약 확인의 현실

브라우저 자동화로 예약 사이트를 조회하는 것은 실무에서 잘 안 된다. 봇 차단과 동적 렌더링 때문이다. **2회 실패하면 즉시 다음으로 넘어간다.**

효과적인 순서:

1. **전화** — 성수기 취소분은 전화 상담원이 실시간 재고를 가장 정확히 안다
2. **공식 예약 사이트 URL을 사용자에게 직접 제공**
3. **예약처가 여러 곳일 수 있음을 먼저 확인** — 같은 공원 안에서도 운영사가 갈린다
4. **취소분 감시 타이밍 안내** — 도착 2～3일 전에 몰린다

산출물에는 **URL + 전화번호 + 운영사명**을 함께 적는다. 사용자가 직접 처리할 수 있는 형태가 자동화 시도보다 낫다.

## 소스 라우팅 체크리스트

리서치를 시작하기 전에 확인한다.

- [ ] 이 여행지의 공식 기관 사이트를 특정했는가
- [ ] 예약이 필요한 항목의 운영사를 전부 파악했는가 (복수일 수 있음)
- [ ] 네이버 검색 MCP가 연결되어 있는가 (없으면 사용자에게 고지)
- [ ] 지도·좌표를 확보할 수단이 있는가
- [ ] 사용자가 첨부한 URL·문서가 있는가 (`travel-url-ingest`)
- [ ] 계절·시기 정보(폐쇄 기간, 운항 시기)를 확인했는가
