# Travel Intake — 초기 정보 수집 및 트립 브리프 생성

## 이 스킬이 존재하는 이유

여행 가이드 자동 생성에서 재작업을 유발하는 원인은 리서치 실패가 아니라 **전제 조건 누락**이다. 실제 운영에서 반복적으로 발생한 재작업 사례는 다음과 같다.

| 사고 유형 | 실제로 벌어진 일 | 예방 질문 |
|---|---|---|
| 요일 오산 | 전 일정의 요일 표기가 하루씩 밀림 → 11개 페이지 전면 수정 | Q1-3 |
| 차량 제약 미확인 | RV로 통과 불가능한 도로를 일정에 넣음 (터널 폭 2.4m) | Q2-4 |
| 숙소 위치 오해 | 공원 밖 사설 캠핑장을 공원 내로 표기 | Q3-2 |
| 예약처 분산 | 한 공원 안에서도 운영 주체가 달라 예약 사이트가 3곳 | Q3-3 |
| 이미지 부족 | 스팟당 사진 1장 → 2장 이상으로 전면 재작업 | Q5-2 |
| 일러스트 오해 | 스톡 사진 대체용으로 잘못 이해 → 전량 재생성 | Q5-3 |
| 한글 깨짐 | 유니코드 이스케이프로 작성해 전 페이지 한글 파손 | Q6-1 (자동 강제) |
| 지도 부재 | 완성 후 구글맵 연동 요청 → 11개 페이지 재편집 | Q4-1 |

이 스킬은 위 항목을 **작업 시작 전에 전부 확정**한다.

## 실행 규칙

1. **AskUserQuestion을 사용한다.** 텍스트로 질문을 나열하지 않는다.
2. **한 번에 최대 4개 질문**만 담을 수 있으므로, 아래 6개 블록을 **최대 3회 호출**로 나눠 묻는다. 이미 사용자가 제공한 정보는 건너뛴다.
3. 무인 실행(스케줄·헤드리스)이라 질문이 불가능하면 **각 항목의 기본값을 적용하고, 채택한 가정을 산출물 최상단에 명시**한 뒤 진행한다.
4. 수집이 끝나면 **`/tmp/{trip_slug}/trip-brief.json`** 을 반드시 생성한다. 이후 모든 스킬은 이 파일만 읽는다.

## 질문 블록

### 블록 1 — 여행의 뼈대 (필수, 1회차)

**Q1-1. 여행 일정**
일정표 파일(docx/pdf/xlsx), 텍스트 붙여넣기, 또는 "초안부터 같이 짜기" 중 선택.

**Q1-2. 기간·출발지·인원**
- 시작일 / 종료일 (YYYY-MM-DD)
- 출발 도시 및 공항
- 인원 구성: 성인 N명 + 아동 N명(각 연령) + 고령자 동반 여부

> 고령자 동반 여부는 단순 인원 수가 아니라 **일정 강도, 하이킹 난이도, 의료 정보 페이지 구성**을 바꾸는 변수다. 반드시 별도로 묻는다.

**Q1-3. 요일 검증 — 자동 수행 후 확인**
사용자에게 요일을 묻지 않는다. 대신 **먼저 계산한 뒤 사용자에게 제시해 확인받는다.**

```bash
python3 -c "
import datetime
s=datetime.date(2026,8,14); n=11
W='월화수목금토일'
for i in range(n):
    d=s+datetime.timedelta(days=i)
    print(f'Day {i+1}: {d} ({W[d.weekday()]})')
"
```

출력을 그대로 사용자에게 보여주고 "이 요일 매핑이 맞습니까?"라고 확인한다. **요일을 추론으로 적지 않는다.** 이 항목 하나로 전체 산출물이 무효화된 전례가 있다.

### 블록 2 — 이동 수단과 물리적 제약 (필수, 1회차)

**Q2-1. 구간별 교통수단**
전 구간 동일한지, 아니면 구간별로 다른지 (예: RV 7박 → 렌터카 3박). 다르다면 교체 지점의 날짜·장소·시각.

**Q2-2. 차량 상세**
- 렌터카: 차종 등급
- RV/캠퍼밴: **업체 + 모델 + 정확한 피트(ft) 수** — "Standard", "Large" 같은 등급명만으로는 부족하다. 업체마다 다르다.
  - 예: Cruise America Standard = C25(25ft), Large = C30(30ft)
- 편도 반납 여부 및 반납 지점

**Q2-3. 예약 상태**
확정 / 가예약 / 미정 중 선택. 미정이면 예약 체크리스트를 D-day 역산으로 생성한다.

**Q2-4. 차량 통행 제약 검증 — 자동 수행**
사용자에게 묻지 말고, 일정에 포함된 모든 경관도로·터널·주차장에 대해 **직접 조사**한다.

조사 항목:
- 터널 높이·폭 제한
- 도로별 차량 길이 제한
- 트레일헤드 주차장의 대형차 수용 여부
- 견인 차량 통행 금지 구간

발견한 제약은 **경고가 아니라 일정 변경으로 반영**한다. 통과 불가 구간이 있으면 대체 주차장이나 우회 경로를 찾아 일정에 넣는다.

### 블록 3 — 숙박 (필수, 2회차)

**Q3-1. 숙박 유형**
호텔 / 캠핑장 / RV파크 / 에어비앤비 / 혼합

**Q3-2. 공원 내부 vs 외부 — 반드시 명시적으로 구분**
국립공원·주립공원이 포함된 일정이라면, 각 숙소가 **공원 경계 안인지 밖인지**를 표기하고 사용자에게 확인받는다.

산출물에는 항상 다음 형태로 적는다.

```
매디슨 캠핑장 (공원 내 · 훅업 없음)
West Yellowstone Grizzly RV Park (공원 밖 · 서문에서 8km · 풀훅업)
```

> 공원 밖 숙소를 공원 내로 오인 표기해 사용자 지적을 받은 사례가 있다. "공원 내" / "공원 밖"은 **모든 숙소 표기에 필수 접두어**로 취급한다.

**Q3-3. 예약처 확인 — 자동 수행**
같은 공원 안이라도 운영 주체가 갈리는 경우가 흔하다. 캠핑장별로 예약처를 개별 조사한다.

| 예시 (옐로스톤) | 예약처 |
|---|---|
| 매디슨·그랜트빌리지·브리지베이·캐니언·피싱브리지 | Xanterra |
| **매머드·인디언크릭·슬라우크릭·토어폭포** | **Recreation.gov** |
| 콜터베이 RV파크 (그랜드티톤) | Grand Teton Lodge Company |

"검색해도 안 나온다"는 문의의 대부분은 예약처가 다르기 때문이다. 예약처와 전화번호를 함께 제시한다.

**Q3-4. 훅업·편의시설 필요 조건**
전기/수도/오수 훅업 필요 여부, 샤워·세탁 필요 여부. RV 여행이면 **훅업 없는 밤이 며칠까지 허용되는지** 확인한다.

### 블록 4 — 지도·경로 연동 (필수, 2회차)

**Q4-1. 지도 연동 수준** *(기본값: 전체)*

| 옵션 | 산출물 |
|---|---|
| **전체 (기본)** | 날짜별 노션 페이지 내 지도 임베드 + 모바일 내비 딥링크 + 스팟별 좌표 링크 + KML/CSV 파일 |
| 링크만 | 날짜별 경로 URL만 |
| 없음 | 지도 관련 산출물 생략 |

**Q4-2. 구글 계정 저장 방식 안내 — 질문이 아니라 고지**
사용자가 "구글맵에 자동 저장"을 기대할 수 있으므로 **먼저 알린다.**

> 구글은 개인 "저장됨(Saved)" 목록에 외부에서 장소를 추가하는 공개 API를 제공하지 않습니다. Places API는 읽기 전용입니다.
> 따라서 **Google My Maps에 KML을 임포트하는 방식**으로 처리합니다. PC 브라우저에서 3분이면 71개 장소를 한 번에 올릴 수 있고, 임포트한 지도는 휴대폰 구글맵 앱의 "저장됨 → 지도" 탭에 나타납니다.

이 고지를 생략하면 작업 후반에 반드시 같은 질문이 나온다.

**Q4-3. 좌표 정밀도 정책 — 자동 적용**
국립공원·산악 지역의 전망대와 pull-out은 정식 주소가 없다. **모든 지도 링크는 장소명이 아니라 위경도 좌표로 생성한다.**

```
https://www.google.com/maps/search/?api=1&query={lat},{lon}
```

### 블록 5 — 콘텐츠 깊이와 시각 자료 (필수, 3회차)

**Q5-1. 스팟별 서술 깊이** *(기본값: 상세)*

상세를 선택하면 각 스팟마다 다음을 모두 작성한다.
- 관람 포인트 (무엇을 봐야 하는가)
- 역사·유래·형성 과정
- **주차 방법** (대형차 가능 여부 포함)
- **추천 관람 시간대** (일출·일몰 기준 포함)
- 소요 시간, 난이도
- 현지 팁·주의사항 (리뷰 기반)

**Q5-2. 스팟당 최소 이미지 수** *(기본값: 2장)*
`travel-image-search`가 이 값을 하한선으로 강제한다. 하위 소제목(subheading)이 있으면 소제목마다 별도 이미지를 배정한다.

**Q5-3. AI 일러스트 생성 여부** *(기본값: 생성)*
생성하는 경우 다음 두 가지를 **모두** 만든다. 이 둘은 용도가 다르다.

| 종류 | 개수 | 용도 |
|---|---|---|
| 전체 여정 요약 일러스트 | 1장 | 메인 페이지 상단 |
| 날짜별 요약 일러스트 | 일수만큼 | 각 날짜 페이지 상단 |

> **중요**: AI 일러스트는 **스톡 사진의 대체재가 아니다.** 그날의 동선·주요 방문지·시간대·계절감을 한 장에 담은 여행 가이드 삽화다. 스톡 사진(Pexels)은 별도로 계속 삽입한다. 이 둘을 혼동해 전량 재생성한 사례가 있다.

**Q5-4. 아동 교육용 별도 페이지** *(아동 동반 시 기본값: 생성)*
여행지 특성에 맞춰 아이가 읽을 수 있는 독립 페이지를 만든다.
- 자연·국립공원 → 동물 도감, 지질·지리 이야기
- 도시·역사 → 인물·사건 이야기, 건축 도감
- 해양 → 해양생물 도감

각 항목에 사진을 넣고, 부모가 현장에서 읽어줄 수 있는 **설명 스크립트**를 포함한다.

**Q5-5. 참고 자료**
기존 노션 페이지, 지인이 만든 일정표, 블로그·카페 URL 등. **네이버 카페/블로그 URL이 있으면 `travel-url-ingest` 스킬로 본문을 확보한다.**

### 블록 6 — 산출물과 연동 대상 (필수, 3회차)

**Q6-1. 산출물 선택** *(복수 선택, 기본값: 노션 + 지도 파일)*
- Notion 가이드북 (메인 + 날짜별 + 참고 자료)
- Google Calendar 등록
- PowerPoint 슬라이드
- Excel 예약 현황표
- KML / CSV 지도 파일

**Q6-2. 노션 부모 페이지**
URL 또는 페이지 ID. 없으면 워크스페이스 루트에 생성.

**Q6-3. 언어·문체** *(기본값: 한국어 존댓말, 번역투 금지)*
한국어 산출물은 `moai-content:humanize-korean` 기준을 따른다.
