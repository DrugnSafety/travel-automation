# Travel Receipt OCR — 영수증에서 지출 원장까지

## OCR을 따로 부르지 않는다

**영수증을 읽는 것은 Claude 자신이다.** Read 도구로 이미지를 열면 그 자리에서 글자가 보인다. 외부 OCR API를 붙이면 오히려 정확도가 떨어지고, 손글씨 팁이나 흐릿한 도트 프린터 영수증에서 더 그렇다.

스크립트가 맡는 일은 사람이 눈으로 하면 틀리는 것들이다 — 파일 정규화, 형식 검증, 중복 판정, 대사 계산.

```
영수증 파일
   │
   ├─ prepare   (스크립트)  회전 보정 · 리사이즈 · PDF 페이지 분할
   │
   ├─ 읽기      (Claude)    이미지를 직접 보고 항목 추출
   │
   ├─ validate  (스크립트)  형식 · 범위 · 중복 점검
   │
   ├─ 확인      (사용자)    애매한 것만 물어본다
   │
   ├─ 등록      (Notion)    행 추가 + 원본 이미지 첨부
   │
   └─ reconcile (스크립트)  예상 대비 차이 계산 → 요약 페이지 갱신
```

## 1. 준비

```bash
python3 scripts/receipt_intake.py prepare \
    --inputs /mnt/user-data/uploads/*.jpg /mnt/user-data/uploads/*.pdf \
    --out /tmp/{trip_slug}/receipts
```

- 세로로 찍은 영수증이 눕는 사고를 EXIF 회전으로 막는다
- 4000px 사진을 2200px로 줄인다. 원본 크기로는 읽기가 느리고 정확도 이득도 없다
- PDF는 페이지별 PNG로 쪼갠다 (`pdftoppm` 필요 — 없으면 `apt-get install -y poppler-utils`)
- HEIC는 `pillow-heif`가 있어야 한다. 아이폰 사진이 대부분 HEIC다
- **해상도가 낮으면 경고가 뜬다.** 그 영수증은 추출 결과를 반드시 사용자에게 확인받는다

`manifest.json`에 정규화된 파일 목록이 나온다. 이걸 순서대로 Read로 연다.

## 2. 영수증에서 읽어낼 것

| 필드 | 규칙 |
|---|---|
| `merchant` | 영수증 상단의 상호명 **원문 그대로**. 번역하거나 정리하지 않는다. 중복 판정의 키다 |
| `date` | `YYYY-MM-DD`. 미국 영수증은 `MM/DD/YYYY`, 유럽은 `DD/MM/YYYY`다. **08/09를 8월 9일로 읽을지 9월 8일로 읽을지는 나라를 보고 판단한다** |
| `currency` | ISO 3자리. 기호만 있으면 국가에서 추론하되 `confidence`를 낮춘다 |
| `amount` | **최종 청구액**. 아래 "총액의 함정" 참조 |
| `tax` | 있으면 넣는다. 없으면 `null` — 0으로 채우지 않는다 |
| `category` | 아래 매핑표 |
| `payment_last4` | 카드 뒷 4자리만 |
| `line_items` | 판단에 필요한 만큼만. 영수증 전체를 옮겨 적지 않는다 |
| `confidence` | `high` / `medium` / `low`. 스스로에게 정직할 것 |
| `notes` | 애매했던 점을 남긴다 |

### 총액의 함정 — 미국 식당 영수증

**미국 식당 영수증에 인쇄된 TOTAL은 팁을 더하기 전 금액이다.** 손님이 손으로 팁과 최종액을 적어 넣는 구조라, 인쇄된 숫자를 그대로 등록하면 실제 카드 청구액보다 15~20% 적게 잡힌다.

- 손글씨 `TIP`과 `TOTAL`이 보이면 **손글씨 쪽을 쓴다**
- 손글씨가 없으면 인쇄된 총액을 쓰되 `notes`에 "팁 미포함 가능성"을 적고 `confidence`를 `medium`으로 낮춘다
- 사용자에게 "팁 포함 금액이 맞나요?"를 물어보는 편이 낫다

그 밖에 자주 틀리는 곳들.

- **주유소** — 펌프 영수증에는 갤런 수와 단가가 함께 찍힌다. `갤런 × 단가 ≈ 총액`이 맞는지 검산하면 자릿수 오독을 잡아낸다
- **캠핑장·주차장** — 며칠치를 한 장에 찍는다. 날짜는 **결제일**을 쓰고 기간은 `notes`에 남긴다
- **여러 장으로 나온 영수증** — 하단에 `1 of 2` 같은 표시가 있다. 합치기 전에 중복 등록하지 않도록 주의
- **환불·취소 영수증** — 음수로 넣지 말고 별도 행으로 만들어 상태를 `환불예정`으로 둔다
- **외화 결제** — 영수증 금액은 현지 통화, 카드 청구는 기준 통화다. `원화폐 금액` 칼럼에 `CAD 84.20 @1.37`처럼 원문과 환율을 남기고, 숫자 칼럼은 기준 통화로 환산해 넣는다

### 분류 매핑

| 영수증에 보이는 것 | 분류 |
|---|---|
| 주유소 브랜드(Exxon·Shell·Sinclair·Conoco), gallons, unleaded | 연료 |
| 식당, cafe, grill, lodge dining, coffee, 팁 란 | 식비 |
| Walmart·Target·Safeway 등 마트, grocery | 식비 (단, 침구·조리도구 같은 내구재가 섞였으면 **행을 나눈다**) |
| campground, RV park, KOA, lodging, hotel, inn | 숙박 |
| entrance fee, park pass, admission, tour | 입장료 |
| RV rental, propane, dump station | RV |
| 렌터카 업체, toll, parking | 렌터카 |
| 기념품, gift shop, junior ranger | 기타 |

마트 영수증에 침구와 식료품이 섞여 있으면 **한 행으로 뭉개지 말고 둘로 나눈다.** 나중에 "장비에 얼마 썼지"를 물어볼 때 답이 나오지 않는다.

## 3. 검증

```bash
python3 scripts/receipt_intake.py validate \
    --records records.json \
    --brief /tmp/{trip_slug}/trip-brief.json \
    --ledger /tmp/{trip_slug}/ledger.json
```

`ledger.json`은 Notion `query-data-sources`로 기존 행을 뽑아 저장한 것이다. 이게 있어야 **같은 영수증을 두 번 올리는 사고**를 막는다.

검증이 잡아내는 것: 필수 필드 누락, 음수·비현실적 금액, 세액이 총액보다 큰 경우, 통화 코드 오류, 알 수 없는 분류, 해석 불가 날짜, 여행 기간 밖 날짜, 배치 내 중복, 원장 중복, 낮은 확신도.

**오류가 하나라도 있으면 등록하지 않는다.** 고치거나 사용자에게 물어본다.

## 4. 사용자에게 물어볼 때와 그냥 넣을 때

물어보는 비용이 잘못 넣는 비용보다 싸다 — 다만 매번 물으면 쓸모가 없어진다. 기준은 이렇다.

**그냥 넣는다**: `confidence: high`이고 검증을 통과했고 기존 예상 항목과 충돌하지 않을 때.

**물어본다**:
- 팁이 포함됐는지 불확실한 식당 영수증
- 금액이 예상 항목의 2배를 넘을 때
- 마트 영수증을 두 분류로 나눠야 할 때 — 어떻게 나눌지
- 통화나 날짜 형식이 애매할 때
- 기존 '예상' 행을 실제 금액으로 **덮어쓸지, 새 행을 추가할지**

마지막 항목이 특히 중요하다. **예상 행을 말없이 덮어쓰면 원래 예산이 얼마였는지가 사라진다.** 기본 동작은 새 행 추가이고, 예상 행은 상태만 바꾸거나 그대로 둔다.

## 5. 등록

행 하나당 다음을 채운다.

```
항목        : {가맹점} — {한 줄 요약}      예) "Walmart Bozeman — 침구·조리도구"
분류        : 매핑표대로
금액(USD)   : 기준 통화로 환산한 최종 청구액
상태        : 확정·결제완료
결제수단    : 카드 뒷 4자리로 판별
결제일      : 영수증 날짜
가맹점      : 원문 상호명
원화폐 금액 : 외화일 때만  "CAD 84.20 @1.37"
영수증      : 원본 이미지 첨부
메모        : 팁 포함 여부, 기간, 애매했던 점
```

원본 이미지는 `notion-create-file-upload`로 올려 `영수증` 칼럼에 붙인다. **이 단계를 건너뛰지 말 것.** 몇 달 뒤 세금이나 카드 이의제기에서 필요한 것은 숫자가 아니라 영수증 자체다.

### 개인정보

- **카드번호는 뒷 4자리만 남긴다.** 전체 번호가 찍힌 영수증이 드물게 있는데, 그대로 Notion에 올리지 않는다
- 서명란·이름이 크게 찍힌 영수증은 그대로 첨부해도 되지만, 텍스트로 옮겨 적지는 않는다

## 6. 대사와 요약 갱신

```bash
python3 scripts/receipt_intake.py reconcile \
    --records records.json --ledger ledger.json --out report.json
```

분류별로 **이번에 등록한 실제 금액 vs 기존 예상 금액**을 나란히 보여주고, 예산을 넘긴 분류와 갱신 후보가 되는 예상 행을 짚어준다.

그다음 `travel-expense-db`의 **경비 총괄 페이지를 다시 계산**한다. 데이터베이스만 고치고 요약 페이지를 두면 두 숫자가 갈라진다. 최소한 다음은 갱신한다.

- 한눈에 보기의 총액·결제완료·변동비
- 분류별 소계와 비중 (합이 100%인지 검산)
- 현금 흐름 표의 해당 시점 행

## 여행 중 현실 — 통신이 안 될 때

옐로스톤 같은 곳은 며칠씩 데이터가 안 터진다. Notion에 바로 못 올린다.

- 영수증을 그때그때 찍어두기만 하고, **파일명에 날짜를 넣어둔다** (`0815_oldfaithful.jpg`)
- 통신이 되는 곳에 도착하면 **한 번에 배치 처리**한다. `prepare`가 여러 파일을 한 번에 받는다
- 배치가 커지면 분류별로 나눠 확인받는 편이 낫다. 20건을 한 번에 물으면 대충 넘어가게 된다

## 자주 나오는 실패

| 증상 | 원인 / 조치 |
|---|---|
| HEIC를 못 연다 | `pip install pillow-heif --break-system-packages` |
| PDF가 변환되지 않는다 | `apt-get install -y poppler-utils` |
| 금액을 계속 틀리게 읽는다 | 해상도 부족. 영수증을 화면 가득 채워 다시 찍어달라고 요청 |
| 같은 항목이 두 번 들어갔다 | `--ledger`를 안 넘겼다. 등록 전 항상 현재 DB를 내려받을 것 |
| 합계가 요약 페이지와 다르다 | 요약 페이지를 재계산하지 않았다. 6단계는 선택이 아니다 |
| 분류가 뒤죽박죽이다 | 마트 영수증을 한 행으로 넣었다. 내구재와 식료품을 나눌 것 |
